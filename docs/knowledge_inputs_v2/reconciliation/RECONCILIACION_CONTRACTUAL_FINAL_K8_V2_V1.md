- Entrada: diagnosis forense R1–R8 entregada en esta conversación y [evidencia original V2-R4][v2-index], freeze SHA-256 `23d7e7f0ce2c5edde5738724adad63a20113da01bcdd712487fd9d9c2e43c7b6`.

- [K7 Desktop][k7-report] conserva 68 contratos PASS. Se leyeron el log original y los tests; no se ejecutó Node, Electron ni build.
- Se verificaron 629 pins de freeze, 538 hashes de evidencia V2, 11 archivos HEAD archivados, 4 artefactos Desktop y 6 fuentes Desktop relevantes: cero drift. Los ejemplos de funciones en la matriz están presentes como PASS en el JUnit existente; no son sólo nombres de tests no ejecutados.

`SATISFIED` significa respaldado por evidencia contractual existente y vigente dentro de ese alcance. No significa que V2 haya pasado ni que todos los formatos/caminos se hayan probado en sus 35 intentos. `VIOLATED` requeriría una contradicción observable con el KI-INV exacto. `NOT_EVIDENCED` se reservaría para falta de evidencia pertinente, no para falta de cobertura en V2 cuando existe evidencia contractual independiente.

### Fundamento observable y límites de esta reconciliación

- **R1:** 010/014 no admitieron documentos; las búsquedas terminaron `REMOTE_SEARCH_DISABLED`, sin efectos en archivos/Memory. El [adapter][adapter] construyó el marcador a partir de la existencia de tool calls. La norma §4/36/37 no permite atribuir authority al producto sin evidencia independiente. No se observó esa evidencia.
- **R2:** el [adapter][adapter] crea target y peer/foreign con el mismo state y mantiene target abierto. [KnowledgeLease][lease] es de propietario único; [test_k1_recovery][test_k1_recovery] exige explícitamente el rechazo de una segunda instancia. §8 y KI-INV-029 requieren aislamiento de scopes, no concurrencia de múltiples propietarios. Este fallo de preparación es composición inválida del fixture, no prueba de un defecto de aislamiento.
- **R3:** lectura expresa de §§26–28, §51 y §53: no se exige un JSON final de facts/relation/abstain/natural_response. El wrapper de evidencia JSON y las citas estructurales son contratos diferentes. Los valores y citas naturales de 002/005 y la separación de orígenes de 012/8K no crean un PASS V2; sólo permiten separar la exigencia extra de una violación de V1.
- **R4:** §23 permite admitir menos y KI-INV-028 permite cero. §25 y KI-INV-026/027 impiden ampliar presupuestos o desplazar contenido obligatorio. Kite/4K necesitaba 230 tokens de cápsula completa frente a cap 225; quedó truncado. Lumen/4K recuperó Knowledge pero admitió sólo Memory; en 8K entraron ambos. La resolución acepta el principio de capacidad acotada, no convierte esos FAIL en PASS ni afirma admisión universal de una/dos/tres fuentes.
- **R5:** §21 exige Exact/FTS sin embeddings; §22/47 y KI-INV-037 mantienen semantic opcional. No hay promesa de traducir `procedimiento` a `procedure`, `soporte` a `support` o las tres materias españolas a documentos ingleses. La expectativa de V2 no crea esa obligación.
- **R6:** el recognizer es acotado y preserva contenido no reconocido; se observó señal con palabras de comparación/presentación. La selección vacía bajo el floor estricto no prueba que Exact/FTS haya dejado de funcionar: existe evidencia positiva independiente, con semantic DISABLED, del mismo baseline. Ningún KI-INV exige recall perfecto para cualquier wording. El cierre V6/post-cert constituye evidencia de los contratos evaluados, no una promesa de comprensión lingüística universal.
- **R7:** el floor se aplica a cada chunk contra una señal global; una fuente de una materia puede no cubrir más de la mitad de una consulta de varias materias. Esto explica 003/016/020 sin demostrar ausencia del camino Exact/FTS. §51 exige probar source conflict; no prescribe query splitting por materias ni cualquier cardinalidad/prompt. No se excluye de READY la capacidad de tratar conflictos dentro del alcance contractual.
- **R8:** `r1` y `r2` activaron el control de identificadores ausentes. El lifecycle real de Iris/Mica conservó source identity, nueva revisionId, r2 current y r1 SUPERSEDED. KI-INV-002/003 no dicen que el texto de una consulta deba transformarse en filtros de revisión; tampoco permiten que el documento autoestablezca lifecycle. No se observa contradicción con dichos invariantes.

No hay fila `VIOLATES_V1_INVARIANT` ni `UNRESOLVED_CONTRACTUALLY` en esta reconciliación final. Se resuelve la duda anterior de R6–R8: la garantía universal específica exigida por esos casos no tiene un KI-INV que la imponga. Esto no borra los misses, no afirma calidad universal y no elimina las obligaciones cuantitativas de §49 o E2E de §51. No se crean subsets post-outcome ni se recalculan métricas V2.
