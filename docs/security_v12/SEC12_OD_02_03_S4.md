# SEC12-OD-02 y mínimo S4 de SEC12-OD-03

Decisión explícita del usuario recibida el 2026-10-03. Alcance exclusivo: S4.
No autoriza S5 ni cierra el modelo completo Environment/Secrets de S6.

## SEC12-OD-02 — Equilibrado (cerrada)

Configuración productiva común en `local_cli/process_config.py`:

| Parámetro | Valor |
|---|---:|
| stdout retenido | 102400 bytes (100 KiB) |
| stderr retenido | 102400 bytes (100 KiB) |
| vista legacy combinada publicada, incluidos marcadores | 102400 bytes |
| timeout default | 120 s |
| timeout máximo efectivo por operación/policy | 600 s |
| cleanup grace | 5 s |
| launches simultáneos en el servicio compartido principal/hijos | 2 |

El usuario eligió ambas recomendaciones previas; se conserva también el cap
combinado de publicación de la recomendación Equilibrado. Cada stream mantiene
su propio cap y flags. `truncated=true` si cualquiera excede su límite o si la
vista combinada excede el suyo. PID/exit/outcome no se pierden al truncar.

Estos límites son operacionales: buffers, supervisión y admisión de launches de
Nova. No son cuotas OS preventivas, aislamiento físico, ni límites de CPU/RAM,
filesystem/red o número de procesos internos creados por un shell.

El campo público `timeout` conserva su schema Core. Application liga el timeout
efectivo (entre 1 y 600 s), límites y argv en el request exacto aprobado. La
configuración puede inyectarse por composición host/policy, no por argumentos
extra del LLM; no se añadió UX/configuración general ajena a S4.

## SEC12-OD-03 — Compatible mínimo (mínimo S4 cerrado)

Base permitida, sin herencia implícita fuera de estos nombres:

`PATH`, `SystemRoot`, `WINDIR`, `COMSPEC`, `PATHEXT`, `SystemDrive`, `TEMP`, `TMP`,
`HOME`, `USERPROFILE`, `HOMEDRIVE`, `HOMEPATH`, `APPDATA`, `LOCALAPPDATA`, `LANG`,
`LANGUAGE`, `LC_ALL`, `LC_CTYPE`, `TERM`, `NO_COLOR`.

Selección case-insensitive. La denylist de credenciales conocidas y los prefijos
Nova/provider prevalecen incluso sobre una allowlist explícita. No se transfieren
material de grants/approval, claves de provider, `NODE_OPTIONS`, `PYTHONPATH`,
SSH agent/proxies ni variables especiales de hooks/inyección no necesarias.

El launch recibe un snapshot nuevo e inmutable de la base efectiva. El snapshot
original de contexto Core y el environment global/provider no se modifican.
Los valores efectivos, no una promesa de aislamiento, participan del digest.

Conservar perfil/configuración permite que herramientas instaladas lean su
configuración normal, que puede contener credenciales o hooks en archivos. S4
no impide esas lecturas ni todas las acciones internas del shell. Tampoco
clasifica semánticamente cada valor de PATH/perfil ni garantiza ausencia de
secretos en archivos u output. Grants/UX/pass explícito y redacción completa
siguen pendientes de S6; no se declara SEC12-OD-03 cerrada en su alcance completo.

## Frontera de autorización y supervisión

El one-shot grant autoriza el launch tras su validación final. Su expiración no
se usa como un lease físico retroactivo de todos los efectos del proceso.
Después del launch se respetan el deadline Core y el timeout efectivo aprobado.
Cancel/timeout posteriores al inicio mantienen efecto desconocido, aun cuando
se confirme la terminación de los miembros medidos. No hay retry automático.

El modelo único es `HOST_UNISOLATED`. Job Objects/process groups se usan sólo
para lifecycle best-effort. No hay sandbox, elevación, seguridad externa ni
claims de contención universal.
