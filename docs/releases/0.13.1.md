# Nova 0.13.1

This patch fixes Unicode transport in the standalone Windows application. It builds on the Nova Desktop interface introduced in 0.13.0.

## Fixes

- Configure the frozen Python backend's standard streams as UTF-8 before startup, rather than relying on environment variables ignored by the bundled interpreter.
- Preserve accented characters, non-Latin text and emoji in responses and workspace snapshots. This also prevents encoding failures during state refresh after stopping a response.
- Keep the desktop package, Python package, README and About version aligned at 0.13.1.
- Make manual installed-app checks derive the expected release version instead of assuming 0.13.0.

## Windows distribution

Download `Nova-0.13.1-windows-x64-setup.exe` and its SHA256 checksum. The installer includes the backend, its Python dependencies and the native browsing component. Ollama and a compatible installed model remain external requirements.

The installer is unsigned. Windows may show a publisher warning or block execution according to local policy. The encoding correction applies to new exchanges; it cannot reconstruct characters already lost in saved conversations.

## Validation

Seven packaging regression tests passed. The Windows production build and an isolated NSIS install/run/uninstall passed, including the visible About version, Unicode chat history, Stop cancellation, a subsequent message and bundled WebView2 cleanup. Tests used a private profile and an owned local Ollama-compatible fixture; no real model was used.

See the [validation report](https://github.com/j-hernandez-dev/nova-assistant/blob/v0.13.1/docs/releases/0.13.1-validation.md) for hashes, results and limitations. This does not establish clean-VM acceptance or real-model performance.
