# Windows UTF-8 rebuild validation

Review date: **2026-10-27, America/Mexico_City**. Package version: **0.13.0**.

## Change

The frozen backend now explicitly configures stdin and stdout as strict UTF-8 and stderr as UTF-8 with diagnostic escaping, immediately after multiprocessing startup handling and before importing the application. This removes its dependency on Windows' default text encoding or interpreter environment handling.

The previous package emitted Windows-encoded JSONL that Electron decoded as UTF-8. It also failed to serialize a snapshot containing characters outside that encoding. Three new regression cases reproduce the old failure under CP1252 and pass with the fix.

## Isolation and limits

The installed validation used a separate NSIS app identity, executable name and updater-cache name. Its Electron executable, application archive, backend and browser files were hash-checked against the production package. The QA wrapper used store compression; production retains its normal compression. The application remained in packaged mode, with known folders redirected to private test locations before production startup.

The owned Ollama-compatible fixture streamed `¡Hola! ¿Cómo estás? áéíóú ñ — 中文 🚀`, kept one response open until Stop was clicked, and served a subsequent response. No real model or user conversation was used. The first two fixture preparation attempts used an unsupported endpoint variable and did not pass; their logs remain outside Git. The final checks use `OLLAMA_HOST` and passed.

The production installer remains **unsigned**. Windows Sandbox was not rerun because its earlier Application Control block for unsigned installers remains unresolved. No security policy was weakened. These results do not claim acceptance on a clean Windows VM or a real-model campaign.

The normal Nova installation in `C:/Program Files/Nova` was not replaced. Run the rebuilt production installer to update that installation and apply the fix there. Existing chats already containing replacement characters are not repaired by changing the transport encoding.

The manual installed-app checker is retained in `packaging/windows/installed_app_check.cjs`. It uses only private test data and an owned loopback service. Full logs and screenshots remain outside Git.
