## Scope and limits

The QA installer used a distinct application identity, process name and updater-cache name, with store compression. Its application archive, executable, backend and native browsing component were hash-checked against the production payload. The application remained in packaged mode; known folders were redirected before its main entry point ran. No developer Python, Node or .NET runtime was exposed on the application PATH. Developer Node drove the external test controller.

Chat tests used an owned local Ollama-compatible HTTP service, not a real model or user conversation. The normal Nova installation and preferences were unchanged. Installing the production setup is still necessary to update that installation.

The production setup is **unsigned**. Windows Sandbox was not rerun because its previous unsigned-code Application Control rejection remains unresolved. No security policy was weakened. These results do not claim clean-VM acceptance or a real-model campaign.

Existing saved replacement characters cannot be reconstructed by the encoding fix. Historical 0.13.0 results retain their original versions and hashes.
